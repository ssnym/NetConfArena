# Task dataset

`task/` contains the released benchmark data, its runtime loader, and suite
metadata. Task-construction, rendering, probing, and validation utilities live
under `scripts/pipeline/`.

## Layout

- `01.*` through `96.*`: one directory per task. Each directory contains the
  parameterized JSON template and its `params.yaml` value pools.
- `all_tasks.json`: ordered registry consumed by the benchmark. Its array index
  is zero-based; `main.py --task_index` exposes a one-based interface.
- `task_loader.py`: resolves parameters, logical topology, physical adapters,
  interface names, configurations, and test cases for a selected seed.
- `router_capabilities.yaml`: runtime device/module capability data required by
  `task_loader.py`.
- `task_stats.json` and `task_stats.csv`: per-template statistics generated by
  `scripts/compute_task_stats.py`.
- `task_taxonomy.json` and `TASK_TAXONOMY.md`: machine-readable and readable
  classifications of the 96-task suite.

## Template contents

Each task JSON defines its scenario and goals, parameter schema,
`topology_model`, `topology_attributes`, startup/reference configurations, and
executable test cases. `params.yaml` supplies seed-dependent value pools such
as device names, address ranges, prefix lengths, and media choices.

Render a registered task in Python with:

```python
from task.task_loader import render_task

task_data = render_task(0, randomize=True, seed=1)
```

For task authoring and the LLM-assisted three-stage process, see
`scripts/pipeline/README.md` and
`scripts/pipeline/docs/TASK_AUTHORING_GUIDE.md`.
